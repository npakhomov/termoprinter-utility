# Режим поддержки: безопасность и проверка

Изменения версии 0.1.10-beta от 16 ноября 2026 года.

## Права Windows

Манифест приложения использует `asInvoker`. При обычном запуске из Проводника
приложение работает без повышения прав. Если пользователь сам запустит его из
повышенного процесса, оно наследует права этого процесса.

| Действие | Права |
| --- | --- |
| Диагностика, ping, ARP, чтение списка принтеров и сети | Обычный пользователь |
| Проверка SHA-256, загрузка и распаковка утилиты | Обычный пользователь |
| Настройки печати Windows | Текущие разрешения выбранного принтера |
| Перезапуск Dodo Label Printer | Процессы текущего пользователя; повышенный/чужой процесс может отказать в доступе |
| Установка драйвера | Отдельный процесс с UAC |
| Создание/изменение порта и очереди | Сначала текущие права, затем отдельный UAC при отказе в доступе |

Повышенный процесс принимает только известные операции, поддерживаемые модели,
три фиксированных назначения принтера и валидный IPv4. Произвольные команды,
пути установщиков или скрипты не принимаются. При установке процесс самостоятельно
скачивает и проверяет пакет в новом каталоге Program Files с ACL только для
Administrators и SYSTEM. Пользовательская распакованная папка не используется
для запуска установщика с повышенными правами. Это также работает при вводе в UAC
учетных данных другого администратора. После операции процесс завершается;
фоновая служба или запланированная задача не создаются.

Если установщик не завершился за 10 минут, приложение не прерывает установку
производителя и не удаляет её рабочую папку или временную очередь. Сообщение
содержит PID, путь и имя очереди. Повторять установку до завершения текущей
нельзя; очистка оставшихся файлов выполняется после её завершения вручную.
Ошибка очистки не подменяет исходную ошибку установки.

Документация Microsoft:

- [Уровень asInvoker и отдельное повышение прав](https://learn.microsoft.com/en-us/windows/win32/secbp/running-with-administrator-privileges/)
- [Права установки драйвера](https://learn.microsoft.com/en-us/powershell/module/printmanagement/add-printerdriver)
- [Add-PrinterPort](https://learn.microsoft.com/en-us/powershell/module/printmanagement/add-printerport)

## Проверенные архивы

Хеши текущих файлов из ранее используемых ссылок Google Drive получены
16 ноября 2026 года и закреплены в `TrustedPackages.cs`.

| Архив | Размер, байт | SHA-256 |
| --- | ---: | --- |
| dd340-utility | 5331256 | `3C74682A41F2C2FBE291D0CDB629E8E59AFD8F9CFADCB5A19DF720A82E5EDF43` |
| bp41-utility | 2695551 | `C3CAE49F8222064A6FE19398C93999598F918E7A05F26F3B4F1A1DAB23B51DD5` |
| dd340-driver | 89473596 | `16EA1096BA4E7B21FC199D474E7A3DE26677CBC59154629449E5C53E30E8A6DC` |
| bp41-driver | 42799311 | `8DF4CB4BB34ED83E257B76A43DCC3C098362578B66609AE2FA31F5F20597579F` |

SHA-256 закрепляет именно эти байты и обнаруживает последующее изменение файла.
Он не является независимой экспертизой содержимого поставщика или его цифровой
подписью. При замене файла в Drive требуется проверить новый пакет и выпустить
версию приложения с обновленным хешем.

Архив проверяется до распаковки и при каждом чтении из кэша. При несовпадении
операция останавливается. HTML-страница вместо ZIP также отклоняется.
Открытый файловый дескриптор архива удерживается на время распаковки, чтобы
проверенный файл нельзя было заменить между проверкой и чтением. Для каждой
распаковки создается новый каталог; старые непроверенные папки не используются.
Перед автоматизацией HPRT требуется закрыть ранее запущенную копию производителя.

Ограничения: до 128 МБ скачанного архива, до 10000 ZIP-entries, до 2 ГБ
распакованных данных. Проверяются выход за границы каталога, абсолютные пути,
дубли имен Windows и NTFS alternate data streams. Кэш архивов сохраняется в
LocalAppData, файлы утилит производителя — в Documents/Label_printer/Verified.
Установщик Dodo Label Printer не является ZIP-архивом и получает актуальную
версию по существующей HTTPS-ссылке; фиксированный хеш для него не добавлялся.

## Удаление приложения

После закрытия всей программы запускается короткоживущий скрытый процесс
Windows PowerShell. Он ожидает завершения приложения, проверяет SHA-256
исходного EXE и удаляет только этот файл. Скрипт передается как EncodedCommand;
файл сценария, служба и постоянная задача на диске не создаются.

Рекурсивного удаления пользовательской папки нет. Драйверы, очереди печати,
документы и программы производителя сохраняются. Измененный или замененный EXE
не удаляется. Рабочее дерево с `.git`/`ThermoPrinterTool.csproj` и обычная
отладочная сборка исключены из автоудаления. При ручном обновлении удаление
откладывается до окончательного закрытия обновленного процесса.

Принудительное завершение процесса/выключение компьютера не выполняет
заключительный код. Если Windows запрещает удаление файла, его нужно удалить
вручную. Автопроверка обновлений выполняется при открытии окна настройки;
ручная проверка также доступна по кнопке. Перед заменой EXE проверяется SHA-256.
Обновление ожидает завершения активной операции и не сбрасывает её статус.
Закрытие окна настройки отменяет сетевые запросы и не запускает отложенный
updater. При отказе запуска/закрытия сбрасывается флаг перезапуска и ожидающий
процесс обновления завершается, чтобы не отключать последующее автоудаление.

## IP и DHCP

Диапазон `200-254` не считается защищенным от конфликтов. Пользователь может
ввести известные границы DHCP-пула; адреса внутри пула исключаются. Если пул
неизвестен, программа прямо сообщает об этом. Автоматического доступа к роутеру
нет. Результат называется IP-кандидатом, а не гарантированно свободным адресом.

Исключаются адреса компьютера, шлюз и существующие адреса принтеров Windows.
ARP выполняется через выбранный интерфейс, затем проверяется ping и повторно
ARP. Ошибка интерфейса не принимается за отсутствие узла. VPN/виртуальные
адаптеры имеют пониженный приоритет. Проверка ограничена 512 кандидатами.

Рекомендация технику: включить DHCP на принтере и создать резервирование адреса
по MAC на роутере. Для статического адреса нужно исключение из DHCP-пула.
Выключенный принтер или будущая DHCP-выдача не определяются по отсутствию ping/ARP.
В окне настройки и журнале диагностики добавлена соответствующая рекомендация.
Модель, IP, маска, шлюз и границы DHCP-пула сохраняются одним снимком перед
скачиванием утилиты. Редактирование полей во время загрузки не изменяет уже
проверенные параметры, передаваемые в HPRT; новое значение требует нового запуска.

- [Microsoft: резервирование и исключения DHCP](https://learn.microsoft.com/windows-server/networking/technologies/dhcp/dhcp-scopes)
- [Microsoft: привязка SendARP к исходному интерфейсу](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-sendarp)

## Проверка

`Tests/SecurityChecks.csproj` — исполняемые проверки без внешних тестовых пакетов.
Проверяют отклонение измененного SHA-256, ZIP traversal и дублей, исключение
DHCP-пула, маски /23, /24, /30 и отказ для некорректных масок, ограничения
повышенного helper-процесса, защиту исходников и точечное удаление тестового EXE.
Дополнительный аргумент позволяет проверить хеши и распаковку реальных архивов.
Добавлены проверки настоящего окна WinForms: ожидание занятой операции при
автообновлении, ручное обновление, отмена при закрытии и неизменность снимка
параметров. На безопасном тестовом процессе проверяется тайм-аут установщика,
сохранение его файлов, завершение с ошибкой и защита исходной ошибки от очистки.

Также вручную проверены окно приложения и обычное закрытие временной single-file
копии: EXE удален, исходники и сборка в рабочем дереве сохранены.

На этом этапе не выполнялись установка/удаление реальных драйверов, создание
очередей Windows и настройка физического принтера. Для проверки UAC и полного
сценария установки нужен контролируемый Windows-стенд с DD340/BP41.

Проверка перед релизом 0.1.10-beta:

- `dotnet restore ThermoPrinterTool.csproj --locked-mode -r win-x86 --force --no-cache` — успешно.
- `dotnet run --project Tests/SecurityChecks.csproj -c Release --no-restore -- ../.security-packages` — 35 проверок, 0 ошибок, включая четыре реальных архива.
- `dotnet publish ThermoPrinterTool.csproj -c Release -r win-x86 --self-contained true --no-restore -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true` — успешно, без предупреждений и ошибок.
- Готовый EXE: запуск меню, отображение окна настройки, штатное закрытие;
  отдельная клиентская копия удалена после выхода, рабочая копия сохранена.

Это регрессионные проверки, а не повторная полная экспертиза AITriage.
